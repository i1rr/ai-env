## Architectural overview

The supervisor at `internal/run` is the single integration spine. The canonical 11-step pre-launch + 9-step teardown sequence is defined once in **Batch 5.5**; every other batch references step numbers there.

```
┌────────────────────────────────────────────────────────────────────┐
│ internal/run.Supervisor                                            │
│                                                                    │
│ pre-launch (canonical 11-step; Batch 5.5):                         │
│   1. lifecycle writer + chmod runDir 0700 + write schema_versions  │
│   2. mint token; start ControlSocket (binds <runDir>/control.sock) │
│   3. backend.Create(EnvSpec{BindMounts, UID, ...})                 │
│        BindMounts (split, NOT whole runDir):                       │
│          <runDir>/ipc/   → /var/run/ai-env/        (agent-RO)      │
│          <shimDir>/      → /var/run/ai-env/shim    (RO)            │
│          <ai-env bin>    → /usr/local/bin/ai-env   (RO)            │
│          empty tmpdir    → <HOME-target>           (HOME shadow)   │
│          per-program shadows over canonical paths:                 │
│            <wrapper>     → /usr/bin/<prog>         (RO)            │
│            <wrapper>     → /bin/<prog>             (RO)            │
│            <wrapper>     → /usr/local/bin/<prog>   (RO)            │
│   4. backend.Start(envID) — netns assigned                         │
│   5. start EgressObserver via ns.WithNetNSPath (netns now valid)   │
│   6. choose ProviderProxy reachability mode + ProxyCarveOuts;      │
│      compute narrowed NetworkPolicy + applyNetworkPolicy           │
│   7. install AIENV-EGR-<8hex> rules at OUTPUT pos 1 via ns.Do      │
│   8. allocate per-provider proxy ports; start each ProviderProxy   │
│      (one listener per provider, upstream Host-header allowlist)   │
│   9. build MCP Gateway + write <runDir>/mcp-servers.json (with     │
│      per-server short-lived tokens) + neutralize workspace MCP     │
│      configs (rename .mcp.json → .mcp.json.ai-env-shadowed)        │
│  10. install host-side shim wrappers in shimDir                    │
│  11. backend.Exec(child cmd)                                       │
│                                                                    │
│ child env: PATH, AI_ENV_RUN_DIR, AI_ENV_CONTROL_SOCKET,            │
│            ANTHROPIC_BASE_URL, OPENAI_BASE_URL, HOME=<shadow>      │
│   NOTE: AI_ENV_CONTROL_TOKEN is NOT in agent env nor in            │
│   mcp-servers.json. It is delivered to each helper instance via    │
│   a per-server short-lived token (see Bucket 4 below).             │
│                                                                    │
│ teardown (canonical 9-step reverse; Batch 5.5):                    │
│   1. stop child; 2. AcceptingShutdown + drain RPCs ≤2s;            │
│   3. drop iptables/pf via ns.Do; 4. stop observer; 5. stop         │
│   ProviderProxy(es); 6. stop MCP logger; 7. backend.Stop+Destroy;  │
│   8. stop ControlSocket; 9. render transcript + atomic-write       │
│   leaks.jsonl + final-summary.md                                   │
└────────────────────────────────────────────────────────────────────┘
        │     │     │     │       │
        ▼     ▼     ▼     ▼       ▼
   policy-  mcp-  network-  shell-  secret-
   decisions calls events   commands scan
              │
              └► filesystem-events.jsonl  ◄ NEW writer
                 transcript.jsonl        ◄ NEW writer
```

All five per-subsystem streams stay as **source of truth**. `leaks.jsonl` is the derived view, atomic-written, every string redacted via the broadened `secrets.RedactSecrets` (rebuilt against `scanners.builtinPatterns()`).

**Correlation key — best-effort, documented limits**: turn IDs minted by supervisor over `ControlSocket`; gap detection robust only for the long-lived MCP shim (per-connection monotonic seq). Shell-mode helpers emit seq=1 always. A compromised agent can call `BeginTurn` or delay it; vector-8 evidence quality is "best-effort under non-compromised agent".

**Schema-version contract**: new streams carry `_schema_version: 1` per record; existing streams record a per-run `schema_versions` map in `run.json` written at supervisor start (step 1, not finalize, so mid-run readers see the map). Readers ignore unknown fields; `_schema_version > 1` → clear error.

## Non-goals (explicit)

- No new auth/authz; no `sbx` replacement; no model-output content classifier; no telemetry export; no live metrics infrastructure; no retroactive aggregation for pre-plan runs.
- **Static-binary shim bypass acknowledged** (statically linked binaries that don't consult PATH or call execve through libc cannot be intercepted by the shim or the absolute-path shadow). Sandbox + network policy + MCP gateway + ProviderProxy remain the real boundary.
- macOS pflog precision is weaker than Linux NFLOG; production target is Linux.
- macOS interpreter-via-file TOCTOU has residual risk on filesystems without `/dev/fd`; documented in platform matrix.
- Slirp4netns has no observer support; `observer_unavailable` documents.
- Sequence-number gap detection is robust only for long-lived MCP traffic.
- Workspace MCP config neutralization (rename to `*.ai-env-shadowed`) modifies the workspace tree at sandbox enter and restores at exit. The supervisor refuses to start when `.gitignore` does not include `*.ai-env-shadowed` (to avoid these artifacts leaking into PRs).
- `EnvSpec.HomeTarget` requires the backend to be able to read the image's `/etc/passwd`; backends that do not support layer inspection fall back to `/root`. Operators using non-root container users with non-root images must set `EnvSpec.HomeTarget` explicitly in policy.yaml (documented).
- `Backend.MappedUID` is mandatory for userns-remap setups; backends that do not implement it limit support to non-remap configurations.

### Autonomous decisions made during the loop

1. **iter1** — picked secrets path = project-local `.ai-env/secrets.local.yaml` (verified against `internal/cli/new.go`); rejected `~/.ai-env/` claim from initial plan as factually wrong.
2. **iter1** — picked stdio middleware over HTTP listener for MCP gateway (rationale: HTTP listener requires per-agent CLI to honor a non-standard env var; stdio middleware works through the CLI's documented `--mcp-config`).
3. **iter1** — picked ProviderProxy unix socket initially; reversed in iter2 after verifying that Anthropic Go/TS SDKs and Claude CLI do NOT documented support `http+unix://`. New rationale: TCP loopback inside container's net-ns via `setns` (preferred), bridge gateway IP (fallback), unix socket (only on feature probe).
4. **iter2** — moved BindMounts from `ExecOptions` to `EnvSpec` at `backend.Create` (rationale: docker/podman cannot add mounts at Exec time; verified by reading `internal/backend/docker/docker.go:440-444`).
5. **iter2** — made shim helper a subcommand of `ai-env` instead of separate binary (rationale: avoids cross-compilation problem; pins helper-version-equals-supervisor-version by construction).
6. **iter2** — broadened `secrets.RedactSecrets` to mirror `scanners.builtinPatterns()` (rationale: the existing RedactSecrets only matched sk-/Authorization/x-api-key; ghp_, AKIA, PEM, etc. would have leaked through the broadened redaction story we depend on).
7. **iter3** — picked `containernetworking/plugins/pkg/ns.WithNetNSPath` over raw `runtime.LockOSThread + setns` (rationale: Go-scheduler thread-migration is a documented landmine; the CNI library handles it correctly).
8. **iter3** — picked simple `AcquireToken-on-PushBranch-entry` over TTL-tracker (rationale: GitHub App installation tokens are non-renewable; the TTL-tracker design was a misunderstanding of the lifecycle).
9. **iter3** — picked Backend.GatewayAddress() method addition (rationale: `docker inspect Gateway` violated Backend interface and silently failed for podman).
10. **iter4** — picked split runDir mount: only `<runDir>/ipc/` into sandbox, not the whole runDir (rationale: agent UID could otherwise enumerate sensitive sibling files like `leaks.jsonl` and `secret-scan.json`).
11. **iter4** — picked side-band primary token delivery via 0400 file readable by container UID + per-server short-lived tokens in mcp-servers.json (rationale: primary token in mcp-servers.json would be visible to the agent CLI, defeating the gateway).
12. **iter4** — picked workspace MCP-config neutralization at Create + restoration at Destroy (rationale: HOME shadow alone doesn't prevent the CLI from merging workspace-local `.mcp.json` per Claude Code docs).
13. **iter4** — picked JSON-aware response scrubber with rolling-buffer streaming (rationale: byte-window replacement would break JSON-RPC framing; per-chunk regex misses cross-chunk secrets).
14. **iter4** — picked fixed canonical-path shadow set + per-image table over runtime probe-via-Exec (rationale: probe runs at step 3 before Start; Exec needs Start; also probe trusts attacker-controlled image output).

### Open questions

- **OQ-1**: Production deployment posture for `EgressObserverMode`: the plan defaults to `Auto` (warn-and-continue on observer failure) so dev machines without CAP_NET_ADMIN can run `ai-env`. Operators should set `--observer-mode strict` in production. The plan documents this; whether operators actually configure strict mode is outside the plan-executor's scope. Suggested follow-up: a `policy.yaml` default that flips to `strict` and emits a one-time setup hint at `ai-env new` time.
- **OQ-2**: Backend-specific `MappedUID` and `HomeTarget` implementation details depend on adapter capabilities (docker rootless, podman rootless, docker_sbx). The plan declares the interface; per-adapter behavior is the plan-executor's call at implementation time. If an adapter can't satisfy either, the supervisor refuses to start that adapter when shim is enabled (already in plan).
- **OQ-3**: macOS production support is explicitly documented as dev-only in the platform matrix; the plan does not propose closing the macOS coverage gap (pflog precision, no `/dev/fd` on some filesystems, no `setns`/`nsenter`). If macOS production support becomes required, a follow-up plan covering Lima/Apple-Virtualization-based Linux microVM hosting is needed.
- **OQ-4**: `cmd/ai-env-helper-launch` shim (the side-band primary-token delivery wrapper in Batch 3.2) is a new tiny binary. The plan treats it as an additional helper subcommand of `ai-env`. The plan-executor should confirm at implementation time that this can be the same `ai-env` binary with a new `helper-launch` subcommand, avoiding another build target.
