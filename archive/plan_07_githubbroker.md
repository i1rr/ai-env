# Plan 07: GitHub Broker

Master plan reference: sections 19 (GitHub broker rules), 25 (export gates), 30 (Milestone 7), 31 (Week 7)

## Objective

Implement the GitHub broker for brokered draft PR creation. The broker enforces branch prefix rules, protected path gates, token scoping, TTL and revocation, and scans PR metadata before submission. After this phase, `ai-env pr` creates a draft PR without exposing a GitHub token inside the sandbox.

## Dependencies

Plans 01-06 must be complete. Export gates from Plan 06 must be wired. Workspace branch name must be available from Plan 02.

## Key decisions from master plan

- Raw GitHub token is never visible inside the sandbox. The broker holds it on the host.
- Preferred credential type: GitHub App installation token (short-lived, repo-scoped).
- PR is always draft by default.
- Only `ai-env/*` branch prefix is allowed.
- No push to protected branches (main, master, etc.).
- No automatic brokered PR if `.github/workflows/**` changed.
- No automatic brokered PR if `.ai-env/**` changed by agent.
- PR title, body, branch name, and commit messages must pass the secret scanner before submission.
- PR body is generated by the host-side broker from sanitized run metadata, not copied directly from raw agent output.
- Token TTL default: 300s. Max: 1800s. Rotate per action, revoke on destroy.

## GitHub broker rules (from policy.yaml)

```yaml
github:
  branch_prefix: ai-env/
  draft_pr_only: true
  block_auto_pr_on_paths:
    - .github/workflows/**
    - .ai-env/**
    - infra/**
    - terraform/**
  require_manual_review_on_paths:
    - Dockerfile
    - docker-compose.yml
    - package.json
    - package-lock.json
    - pnpm-lock.yaml
    - migrations/**
```

## PR body format (broker-generated)

The broker generates the PR body from sanitized run metadata. It must include:

1. Run ID.
2. Agent and task description.
3. Scan summary (number of findings, highest severity).
4. Protected path warnings.
5. List of changed files (top N, truncated if large diff).
6. Explicit notice that this is an automated agent run.

The broker must not:

1. Copy raw agent transcript into the PR body.
2. Include any value that matches secret patterns.

## Token lifecycle

```
ai-env pr fix-tests --draft
  -> ExportGate: check scan results and protected paths
  -> GitHubBroker.Prepare(): validate branch, repo, policy
  -> GitHubBroker.AcquireToken(): obtain short-lived install token
  -> GitHubBroker.PushBranch(): push ai-env/fix-tests to remote
  -> GitHubBroker.ScanMetadata(): scan PR title, body, commit messages
  -> GitHubBroker.CreateDraftPR(): create PR via GitHub API
  -> GitHubBroker.RevokeToken(): revoke or expire token
  -> Log sanitized result
```

## Acceptance criteria

1. Raw GitHub token is not written to workspace files, run logs, shell history, or env-visible sandbox environment.
2. `ai-env pr fix-tests --draft` creates a draft PR on `ai-env/fix-tests` branch.
3. Push to `main` or other protected branch is blocked.
4. `.github/workflows/**` change blocks automatic brokered PR creation.
5. PR title, body, branch name, and commit messages are scanned before submission.
6. PR body is generated from sanitized run metadata, not raw agent output.
7. Token has TTL and is revoked or expired after run ends or `ai-env destroy` is called.
8. Blocked or failed broker actions appear in `policy-decisions.jsonl`.
